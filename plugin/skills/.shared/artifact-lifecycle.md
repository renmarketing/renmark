# Artifact Lifecycle — Reference (single source of truth)

**Shared by every skill that writes, reads, or retires a renmark artifact:**
`audit`, `roadmap`, `finish`, `hygiene`, `orchestrate`, and any skill that
touches `.renmark/`. This file extends CLAUDE.md's "Artifacts carry
provenance and freshness metadata" block — it does not restate it. That block
already requires `artifact_type`, `schema_version`, `created_at`, `source_sha`,
`related_plan`, `generator`, `stale_after`, `dependency_refs` on every artifact
renmark writes. This file adds the fields and rules that block doesn't cover:
ownership, status, invalidation, replacement, and retention/archive.

---

## Lifecycle fields (additive, not a replacement)

Add these alongside the existing provenance block — same top-of-file
metadata convention, same enforcement expectation:

| Field | Meaning |
|---|---|
| `owner` | Who/what generates and is responsible for this artifact — a skill name (e.g. `audit`, `roadmap`) or `Owner` for human-authored files. |
| `status` | `active \| superseded \| retired`. |
| `dependencies` | Paths this artifact was derived from. Overlaps `dependency_refs` from the provenance block — cite that field, don't duplicate it. |
| `invalidated_by` | The *condition* that makes this artifact stale, distinct from `stale_after`'s timestamp — e.g. `"source file changed"`, `"superseding artifact published"`. |
| `replacement` | Path to the artifact that supersedes this one. Required when `status: superseded`. |
| `retention` | `durable \| ephemeral`. Durable artifacts live under `.renmark/memory/`, `.renmark/specs/`, `.renmark/plans/`; ephemeral ones under `.renmark/logs/`, `.renmark/state/`. See CLAUDE.md's canonical-homes list ("All renmark output stays inside the project") for the full directory map — cite it, don't restate it. |

## Retirement policy

Retiring a duplicated or stale artifact **type** (not a bulk directory reorg)
means exactly three things:

1. **Stop generation.** Change the code/skill path that produces new
   instances of the artifact type so it no longer writes new ones.
2. **Leave existing instances on disk** unless they are trivial one-off
   reruns explicitly named in an audit — retirement is not a delete pass.
3. **Redirect readers, backward-compatibly.** Any reader that used to load
   the retired artifact type falls back to reading its `replacement` or
   canonical source. This must be a backward-compatible read, never a hard
   break — a missing retired file must not raise.

### Worked example

The `ORCHESTRATION-BASELINE-2026-08` audit
(`.renmark/audits/orchestration-baseline-audit-2026-08-02.md`) is the
reference case for this policy. It named two first targets for retirement
under these three steps:

- `.renmark/memory/analytics.md` — stale (~27 days at audit time), not
  auto-regenerated by any current code path.
- `.renmark/roadmap/agency-optimization-roadmap.md` — a duplicate of the
  committed, canonical `.renmark/memory/roadmap.md`.

Neither has been deleted by this reference doc; retirement is proposal-only
until the owning skill's generation path is actually changed per step 1
above.

## Why a shared file

Same rationale as `context-taxonomy.md`: one edit point instead of every
skill drifting its own description of what "stale," "superseded," and
"retired" mean. `plugin/skills/.shared/` is skipped by `renmark.lint`, so
this file never trips the command-pair check.

When citing this doc in a SKILL.md or rule block, write:

> *Honor artifact lifecycle rules in
> `${CLAUDE_PLUGIN_ROOT}/skills/.shared/artifact-lifecycle.md`: artifacts
> additionally carry `owner`, `status`, `dependencies` (see
> `dependency_refs`), `invalidated_by`, `replacement`, and `retention`;
> retiring an artifact type stops generation, leaves existing instances on
> disk, and redirects readers to the replacement — never a hard break.*

Do not paste this file's tables into the calling SKILL.md — cite this file.
