# R-0.4 Release Contract — Minimal Independent Inspector

Shape per `release-contract-template.yaml` (governing-methodology-addendum-02.md).
Scope: **narrowed slice of Milestone 5** ("Inspector Framework",
`governing-architecture-roadmap.md:290-292`) — the smallest viable
independent-inspector mechanism that can read R-0.3's canonical ledger
(Work Order / Work Result / Inspection Report / Escalation, now
schema-validated and append-only) and emit its own PASS/FAIL/ESCALATE
verdict, decoupled from the executor that did the work. The full Inspector
registry (Contract/Architecture/Code/Test/Runtime/UI/Risk Inspector
classes), risk-based optional Inspector selection, and Playwright-backed UI
evidence are Milestone 5 in full and stay out of scope here — R-0.4 proves
the mechanism with one minimal inspector shape, not the catalog.

## User value

- **Actor**: The Owner and any Renmark pipeline (`orchestrate`, `feature`,
  `debug`, `finish`) whose Worker output needs a verdict that isn't
  self-graded.
- **Capability**: A Work Result recorded in R-0.3's ledger can be handed to
  a distinct Inspector role — not the Worker/executor that produced it —
  which reads the relevant Work Order, Work Result, and any prior
  Escalation from the ledger and returns a structured PASS/FAIL/ESCALATE
  verdict with cited evidence, itself recorded as a new Inspection Report
  ledger event. The Owner (or a resumed session) can trust that "PASS" in
  the ledger was not asserted by the same role that did the work.
- **Problem addressed**: today's `/renmark:codereview`/`/renmark:verify`
  produce inspection-shaped output, but nothing enforces that the entity
  producing a verdict is mechanically distinct from — and independently
  invoked from — the entity that produced the artifact under review, and
  no verdict is recorded as a schema-validated ledger event alongside the
  Work Result it judges. R-0.3 built the ledger shape for Inspection
  Report; R-0.4 is the first release that actually emits one from a
  dispatch that is provably not the Worker's own self-assessment.

## User journey

- **Starting state**: Post-R-0.3 (v0.39.6). The ledger records Work Order,
  Work Result, Inspection Report, and Escalation events at bounded real
  call sites, but no dispatch path constructs an Inspection Report from a
  role distinct from the Worker — `codereview`/`verify` produce review
  output today, not a ledger-recorded, independently-dispatched verdict.
- **Action**: A pipeline step (e.g. `orchestrate`'s post-wave check, or a
  standalone `/renmark:codereview`-shaped call) reads a Work Result from
  the ledger, dispatches a minimal Inspector role with only the relevant
  Work Order + Work Result + Escalation history (never the Worker's full
  transcript), and the Inspector returns a PASS/FAIL/ESCALATE verdict with
  cited evidence (file/line, test output, or contract clause). The verdict
  is schema-validated and appended to the ledger as an Inspection Report
  event, distinct from and pointing back to the Work Result it judged.
- **Expected result**: for at least one real call site, a Work Result in
  the ledger has a corresponding Inspection Report event, produced by a
  dispatch that is mechanically distinct from the Worker's dispatch (a
  separate inspection execution, not the same role re-asserting its own
  output), with a verdict of PASS, FAIL, or ESCALATE and cited evidence. A
  deterministic, independently-rerun verifier (a fresh subprocess execution
  of the task's own verifier command, decoupled from the Worker's run) is
  the DEFAULT Inspector for R-0.4's minimal scope; the LLM Inspector role
  (`plugin/agents/inspector.md`, built in WP-1) remains available/optional
  for ambiguous, high-risk, or evidence-insufficient cases, but is not
  required at this one wired call site.
- **Failure behavior**: an Inspector verdict missing cited evidence, or a
  verdict attempted by the same dispatch/role that produced the Work
  Result under review, is rejected before it is written to the ledger —
  the emitting path surfaces the rejection rather than silently accepting
  a self-graded PASS.

## Scope

- **Included**: a minimal Inspector role definition (one class — general
  "verdict on a Work Result" inspector, not the full Contract/Architecture/
  Code/Test/Runtime/UI catalog); a verdict schema (PASS/FAIL/ESCALATE +
  cited evidence + reference to the Work Order/Work Result it judges),
  reusing R-0.3's `InspectionReport` ledger schema rather than inventing a
  parallel shape; a dispatch-independence check (the Inspector's dispatch
  identity must differ from the Worker's dispatch identity for the same
  Work Result — mechanical, not a prompt-only promise); wiring at least one
  real call site (e.g. `orchestrate` post-wave or `codereview`) that
  dispatches the Inspector and appends its verdict as a ledger event; a
  reader helper answering "what's the latest verdict for Work Result X";
  tests for verdict schema validation, dispatch-independence enforcement,
  and the self-grading rejection path.
- **Excluded**: the full Inspector class registry (Contract/Architecture/
  Code/Test/Runtime/UI/Risk Inspectors); risk-based optional Inspector
  selection; Playwright-backed UI evidence collection; automatic
  repair-work-order generation from a FAIL/ESCALATE verdict (schema exists
  per R-0.3's Carried F2 note; auto-generation wiring is Milestone 5);
  folding all of `/renmark:verify`/QA/deep-QA/codereview into the Inspector
  layer (bounded proof at one call site only, matching R-0.1/R-0.2/R-0.3's
  "at least one real call site" precedent); closing R-0.2 F1/F2/F4/F5
  (tracked only, per "Carried dependencies" above).
