# Loop Mode — Reuse Map + Integration Recommendations

Bounded resumable agentic loop wrapping plan -> orchestrate -> verify. This artifact
maps the EXACT existing renmark machinery to reuse and answers the integration questions.

## 1. State primitives (renmark/state/, package re-exports both import styles)

### Usage ledger (renmark/state/usage.py) — SPEND source of truth
- File: `.renmark/state/usage.jsonl` (constant USAGE_LEDGER in _core.py). Append-only JSONL.
- `UsageRecord` fields: `ts, run_id, task_id, model, prompt_tokens, completion_tokens`.
  NOTE: there is NO cost/$ field and NO per-run total field on disk — cost is derived at
  render time, not stored.
- `log_agent_call(repo, *, task_id, model, tokens_in, tokens_out, run_id)` — orchestrate
  calls this after each Agent return (haiku/sonnet/opus). Codex tasks are ledgered by
  renmark-execute itself (do NOT double-log).
- Aggregation helpers: `read_usage(repo) -> list[dict]`, `usage_today(repo) -> int`,
  `usage_this_month(repo) -> int`. Both sum prompt+completion tokens, filtered by ts prefix.
  KEY GAP for loops: there is NO usage_by_run_id() aggregator. A per-loop spend total must
  be computed by the loop: filter read_usage(repo) by the loop run_id(s) and sum tokens.
- Cost conversion is NOT in state — $/kT rates live inline in cli/_engine.py dry-run
  (cost_per_kt = {haiku:0.0001, codex:0.05, sonnet:0.003, opus:0.015}) and in roadmap render.
  A loop budget expressed in tokens reuses the ledger directly; a $ budget must re-derive cost.

### Pipeline runtime state (renmark/state/pipeline.py) — RUNTIME, gitignored
- File: `.renmark/state/pipeline.json` (PIPELINE_JSON). PipelineState fields:
  `current_phase (idle|orchestrate|paused), current_plan, wave_index, wave_total,
  completed_tasks: list[int], failed_tasks: list[int], last_updated`.
- `read_pipeline_state`, `write_pipeline_state(... read-modify-write ...)`,
  `clear_pipeline_state`, `pipeline_is_resumable(repo)` (True iff phase in
  {orchestrate,paused} and wave_index < wave_total).
- Wave summaries: `.renmark/state/wave-summaries/wave-N.json` via write_wave_summary /
  read_wave_summary / list_wave_summaries. Each holds task_outputs = SubagentOutput dicts.
  Auto-rotates past WAVE_SUMMARIES_KEEP.

### Pause state (renmark/state/pause.py)
- File: `.renmark/state/PAUSED` (PAUSED_FILE). PauseState fields:
  `run_id, plan_path, last_task_index, reason, ts`. write_pause/read_pause/clear_pause.
- Escalation buckets: `.renmark/state/escalations/task-N/` via escalation_dir.

### Spend queryability summary
- Per-run cost total: NOT stored. Computable: read_usage() filtered by run_id, summed,
  optionally cost-converted via the inline $/kT table. A loop owns this aggregation.

## 2. Budget concept — already exists, in the CLI engine only

- `renmark/cli/_engine.py` Config (from_env): `max_tokens_per_run` (env
  RENMARK_MAX_TOKENS_PER_RUN, default 50000), `max_minutes_per_run` (default 30),
  `max_tasks_per_run` (default 15), max_task_retries (2).
- This is the "budget: 50000 tok / 30 min" header line (_engine.py:277).
- ENFORCEMENT is per single renmark-execute RUN, inside the wave loop (_engine.py:380-390):
  before each wave it checks `tokens_used >= max_tokens_per_run` -> failure_kind=
  "token_budget"; `time.monotonic() > deadline` -> "time_budget"; on hit it skips
  remaining tasks, writes PAUSED, exits 10. tokens_used accumulates r.tokens_out per wave.
- CRITICAL: this budget is (a) per single codex CLI run, (b) measured against tokens_used
  accumulated IN-PROCESS during that one subprocess invocation — it is NOT a cross-iteration
  or persisted ceiling, and it does NOT read usage.jsonl. A multi-iteration loop CANNOT
  reuse this ceiling directly: each plan->orchestrate->verify iteration is its own
  process/dispatch boundary; max_tokens_per_run resets every run.
- The only other "budget" is LIFECYCLE_JSON_BYTE_BUDGET (1KB, unrelated — size guard).

## 3. Lifecycle (renmark/lifecycle.py) — WORKFLOW state only (G12)

- STAGES (ordered): init, brainstorm-complete, plan-drafted, plan-validated, created,
  verified, reviewed, documented, ready-to-release, released, restored.
- NEXT_BY_STAGE routing; created->/renmark:verify, verified->/renmark:codereview.
- LifecycleState fields: feature, branch, github_issue, stage, stages_completed,
  artifacts (dict), human_review_required/completed/for, next_recommended, last_updated.
- write_lifecycle (read-modify-write, validates stage in STAGES), begin_feature (fresh
  reset), next_recommended, clear_lifecycle. next_steps()/skill_class() power hand-off.
- Human-approval gate fields: human_review_required / human_review_completed /
  human_review_for. next_recommended() blocks on a pending gate until completed flipped.
- 1KB BLOAT GUARD: write_lifecycle raises `LifecycleBloatError` if serialized >1024 bytes.
  This is the hard proof that loop runtime state (iteration index, remaining budget,
  per-iteration decision objects) MUST NOT live in lifecycle.json — it is workflow-only and
  would blow the budget. CONFIRMED from code + CLAUDE.md G12 strict-separation rule.
- CONCLUSION: loop runtime state belongs in a pipeline.json-style runtime file (new loop.json),
  NOT lifecycle.json. Lifecycle holds only WORKFLOW identity/stage/artifacts/approval.

## 4. /renmark:resume (plugin/skills/resume/SKILL.md)

- Zero LLM calls, pure file IO. Reads lifecycle.json via read_lifecycle; prints
  Feature/Branch/Stage/Done/Next. Next = state.next_recommended (stage-routed).
- Surfaces pending approval (human_review_required && !completed -> Next: /renmark:approve).
- Step 1.5 validates artifact refs (validate_artifact_refs) — frontmatter freshness/sha.
- It already references pipeline.json "for --resume hints" (governance note). A mid-loop
  resume slots in cleanly: resume reads loop.json (if phase==loop and resumable) and prints
  "Loop iteration K/N, budget X/Y remaining, pending step=<orchestrate|verify>; resume with
  /renmark:loop --resume". Mirror the orchestrate pipeline_is_resumable pattern exactly.

## 5. orchestrate + verify per-iteration invocation

### orchestrate (plugin/skills/orchestrate/SKILL.md)
- Per-task: dispatch isolated subagent -> parse_subagent_response -> log_agent_call ->
  verifier_tail -> write_wave_summary + write_pipeline_state. On clean run: clear_pipeline_state,
  write_lifecycle(stage=created), THEN AUTO-INVOKES /renmark:verify.
- Spend IS captured per-iteration via state.log_agent_call (Agent path) + renmark-execute
  ledger (codex path) -> usage.jsonl. A loop reads usage.jsonl deltas to compute iteration cost.
- Orchestrate's orchestrator-visible completion line: "All N tasks committed (M commits,
  ~$X spent). Running verification..." — bounded, loop-readable.
- IMPORTANT: orchestrate auto-chains into verify already. A loop wrapping both should invoke
  orchestrate and let it flow into verify, OR suppress the auto-verify and drive verify itself
  (cleaner for capturing the decision object). Recommend the loop owns the verify call so it
  reads the .verification.md verdict directly.

### verify (plugin/skills/verify/SKILL.md)
- Goal-backward: parses plan.context goal, extracts N behaviors, runs one shell smoke per
  behavior + bugs.md regression overlap. Reports "M/N requirements verified" + failed names.
- Emits `.renmark/reviews/YYYY-MM-DD-<sha>.verification.md` via summary.write_artifact
  (artifact_type=verification, generator=verify, completion_state complete|partial,
  confidence high|medium, validation_status=validated). summary_lines already include
  passed/total, feature, failed list, regressions, next command.
- The loop reads ONLY the .verification.md metadata + Summary via summary.emit_pointer /
  read_metadata — never the body. completion_state==complete && all behaviors verified is
  the goal_reached signal.

## 6. summary.py + SubagentOutput/Gap — reusable for the decision object

- summary.write_artifact(path, *, artifact_type, body, summary_lines (<=5, <=1200 char/line),
  generator, confidence, validation_status, completion_state, source_sha, related_plan,
  dependency_refs, retry_count, parser_success, schema_compliance) — THE artifact writer.
  Raises SummaryBoundaryError on cap violation. Use it for both loop.json's human-readable
  companion AND each iteration decision record.
- summary.emit_pointer(path,label) -> bounded metadata+Summary string (orchestrator-safe).
- read_metadata, is_stale, git_head_sha, verifier_tail — all reusable.
- SubagentOutput (dispatch.py, frozen): status PASS|FAIL|SKIP, artifact_path, touched_files,
  sha, summary_lines, dependency_notes, token_count, completion_state, confidence, retry_count.
  This is the PRECEDENT shape for the per-iteration decision object — mirror it.
- Gap (init.py:129) is a roadmap-discovery dataclass, not relevant to the loop decision object.

## INTEGRATION RECOMMENDATIONS

### Budget mechanism — RECOMMEND: reuse usage.jsonl + a NEW per-loop ceiling in loop.json
- Do NOT reuse Config.max_tokens_per_run — it is per-single-process, in-memory, resets every
  run, and never reads the ledger. It cannot bound a multi-iteration loop.
- Define loop budget in loop.json: `budget_tokens` (and/or budget_usd) + `spent_tokens`.
  At each iteration boundary, compute iteration spend = sum of read_usage(repo) records whose
  run_id is in this iteration's run_id set (or ts-delta since iteration start), add to
  spent_tokens, persist. Stop the loop when spent_tokens >= budget_tokens BEFORE dispatching
  the next iteration. Reuse the inline $/kT table (lift to a shared const) only if a $ cap is
  wanted. This mirrors _engine.py's pre-wave gate, lifted to the iteration level and made
  persistent. Add a usage_by_run_id() / usage_since(ts) helper to usage.py to make this clean.

### Per-iteration decision object — RECOMMEND: compute in the loop driver, persist to loop.json
- Shape (mirror SubagentOutput): {goal_reached: bool, evidence: str (verify summary line),
  next_action: continue|stop|escalate, model_recommendation: str, estimated_next_cost: int,
  iteration: int, spent_tokens: int, budget_tokens: int}.
- SOURCE: goal_reached + evidence come from the verify .verification.md (read_metadata
  completion_state + emit_pointer summary, NEVER the body). estimated_next_cost from the
  prior iteration's ledger delta (last iteration token spend as the estimate). spent_tokens
  from usage.jsonl aggregation. Computed in the loop skill driver, written via
  summary.write_artifact (artifact_type=loop-iteration) + a compact record in loop.json.

### Continue/stop gate — RECOMMEND: single upfront approval, no per-iteration nagging
- The repo doctrine (plan/SKILL.md:153, feature/SKILL.md:96-99) is the SINGLE-DISPATCH-GATE:
  "there must never be two dispatch gates". A loop must honor this — get ONE upfront approval
  (budget + max-iterations + stop-condition) then run autonomously to a terminal state
  (goal_reached | budget exhausted | max iterations | hard FAIL). Surface a bounded
  per-iteration progress line (like orchestrate's "~$X spent"), but DO NOT prompt mid-loop.
  Only re-prompt on a terminal stop. This fits both the single-dispatch-gate and the
  orchestrator-bounded-output doctrines. Human-approval-gate fields in lifecycle stay for the
  release/merge boundary, not per iteration.

### Resume contract — file ownership
- loop.json (NEW, runtime, gitignored, sibling of pipeline.json):
  `current_phase: loop`, `iteration_index`, `max_iterations`, `budget_tokens`,
  `spent_tokens`, `pending_step (plan|orchestrate|verify)`, `plan_path`, `run_ids: list`,
  `last_decision: {decision object}`, `last_updated`. Add loop_is_resumable() mirroring
  pipeline_is_resumable. pipeline.json continues to own the INNER orchestrate run state
  (wave_index/tasks) — loop.json wraps, does not replace it.
- lifecycle.json: UNCHANGED — only stage (created/verified) + artifact pointers + feature
  identity. NO loop runtime (would trip the 1KB LifecycleBloatError). G12 separation confirmed.
- /renmark:resume: extend to detect loop.json (phase==loop, resumable) and print the
  iteration/budget/pending-step + "resume with /renmark:loop --resume" — zero LLM, same as today.

### Where loop state lives vs lifecycle.json (G12)
- WORKFLOW (lifecycle.json): feature, branch, stage, artifacts, human_review_* — unchanged.
- RUNTIME (loop.json + pipeline.json + usage.jsonl): iteration index, budget/spend, pending
  step, per-iteration decision records, inner wave state, spend ledger. CONFIRMED by the 1KB
  bloat guard and the explicit CLAUDE.md G12 strict-separation rule.

## Summary

- Spend lives in usage.jsonl (UsageRecord: ts,run_id,task_id,model,prompt/completion_tokens) — no cost or per-run total stored; aggregate via read_usage filtered by run_id.
- Config.max_tokens_per_run (50k/30min) is per-single-process and never reads the ledger — NOT reusable as a loop ceiling; define a persisted per-loop budget in a new loop.json.
- Loop runtime state must NOT go in lifecycle.json (1KB LifecycleBloatError, workflow-only G12) — use a pipeline.json-style loop.json; pipeline.json keeps the inner orchestrate run state.
- verify already emits a goal-backward PASS/FAIL .verification.md (completion_state + summary); loop reads metadata/emit_pointer only. orchestrate ledgers spend via log_agent_call -> usage.jsonl.
- Decision object mirrors SubagentOutput shape, computed in the loop driver from verify output + ledger delta; resume extends to detect loop.json (iteration/budget/pending step), zero LLM.
