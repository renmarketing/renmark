# Spec — loop-mode (MVP: bounded, verified, resumable agentic loop)

## Context

PRD Loop Mode (REQ-9..12, approved 2026-06-09): renmark's execution engine is a
bounded, verified, cost-aware, resumable loop wrapping plan → orchestrate →
verify. This MVP builds the safe core; indefinite + scheduled/PR-triggered loops
are deferred. Research (artifact) settled the integration: spend lives in
`usage.jsonl` (tokens, by `run_id`); `Config.max_tokens_per_run` is per-process
and NOT a reusable ceiling; loop runtime state must live in a `loop.json`
(pipeline-style runtime, NOT `lifecycle.json` — G12 / 1KB guard); `verify`
already emits a goal-backward PASS/FAIL `.verification.md`; `orchestrate` already
ledgers spend.

**Decisions (this brainstorm):** budget accepts **both** a token count and a `$`
amount (tracked in tokens — the measurable unit — with a `$` estimate shown);
**single upfront approval, then autonomous** to a terminal state (no per-iteration
prompts — honors the single-dispatch-gate doctrine); the loop **commits each
passing iteration** to the feature branch (safe/revertable) and **gates at finish**
(approval before merge/release/PR/budget-escalation/destructive — REQ-12).

## Goals

1. `/renmark:loop "<goal>"` runs bounded iterations (orchestrate → verify →
   decide) until the goal is verified, budget hit, max-iterations hit, an
   approval gate is pending, or no fresh evidence supports the next action.
2. Cost-aware + bounded (REQ-9): one upfront cost preview + explicit approval of
   budget + max-iterations; never unbounded; never a per-process-only cap.
3. Resumable (REQ-10): loop state in `.renmark/loops/<id>/` survives /clear,
   /compact, crash, new session; `/renmark:resume` recovers it.
4. Context-hygienic (REQ-5/11): the loop reads only verify metadata + ledger
   spend + bounded summaries — never generated code/diffs/full bodies.
5. Human-gated (REQ-12): autonomous within bounds, but stops for approval before
   merge/release/PR/budget-escalation/destructive changes.

## Non-goals (feature-scoped)

- Indefinite autonomous loops; scheduled / PR-triggered loops (deferred).
- Per-iteration human prompting (single upfront gate instead).
- A new cost-tracking system (reuse `usage.jsonl`; add only an aggregation helper).
- Loop state in `lifecycle.json` (G12 — runtime state goes in `loop.json`).
- New runtime deps (stdlib + markdown).

## Architecture

**`renmark/loop.py` — the loop driver (pure-ish orchestration, never reads code).**
- `run_iteration` / `drive_loop` helpers: per iteration → invoke orchestrate on
  the current plan/next-action, run verify (goal-backward + the `--verify` cmd),
  read verify's `.verification.md` PASS/FAIL + the **ledger spend delta** for the
  loop's `run_id`, build a decision object, write `iterations/NNN-summary.md`,
  update `loop.json`, evaluate stop conditions. Reads ONLY verify metadata +
  ledger + bounded summaries (REQ-5/11). Never raises into the caller.
- **Decision object** (SubagentOutput-shaped): `{goal_reached: bool, evidence:
  [..], next_action: str, model_recommendation: str, estimated_next_cost: str}`.
- **Stop conditions:** goal_reached (verify PASS) · spent ≥ budget ·
  iteration ≥ max_iterations · approval-gate-pending · no fresh evidence /
  empty next_action. Each maps to a terminal `status` in `loop.json`.

**`loop.json` (runtime state under `.renmark/loops/loop-<date>-<slug>/`):**
`{goal, verify_cmd, budget_tokens, budget_usd_estimate, spent_tokens, run_id,
max_iterations, iteration, status (running|done|budget-hit|max-iter|awaiting-approval|stalled),
pending_step}`. Sibling files: `goal.md`, `plan.md`, `verification.md`,
`iterations/NNN-summary.md`, `evidence/`. `pipeline.json` holds the inner
orchestrate run (unchanged).

**`renmark/usage.py` (or state.py) — `usage_by_run_id(repo, run_id) -> int`
(+ `usage_since`)** — aggregate token spend from `usage.jsonl` for the loop's
run, so the budget gate is enforceable against real spend.

**`plugin/skills/loop/SKILL.md` + `plugin/commands/loop.md`** — the expert command:
parse `--goal/--verify/--budget(tokens|$)/--max-iterations`; **single upfront
approval gate** (goal + verify cmd + budget [tokens + $ est] + max-iter + cost
preview → Proceed?); then drive the loop, emitting a **bounded per-iteration
progress line** (≤ summary cap) — no mid-loop prompts; on terminal status, report
the bounded verdict and route to `/renmark:finish` (which carries the REQ-12 gates).

**Wiring:** `/renmark:start` routes the vibe-coder path into Loop Mode under the
hood (never says "loop"); `/renmark:resume` detects a `running`/`awaiting-approval`
`loop.json` and prints the resume command + iteration/budget-remaining (zero LLM).

**Defaults (tunable constants):** `--max-iterations` default **5**; default budget
**300k tokens** (shown with a `$` estimate via the plan cost model). Overridable.

## Data flow

```
/renmark:loop "<goal>" [--verify CMD] [--budget 300000|$3.00] [--max-iterations 5]
  → upfront gate: goal · verify cmd · budget (tokens + $est) · max-iter · cost preview → Proceed? [y/N]
  → mkdir .renmark/loops/<id>/ ; write loop.json (status=running, iteration=0)
  → while not terminal:
       iteration N: orchestrate (plan/next_action → commits to branch, ledgers spend)
                  → verify (goal-backward + --verify) → .verification.md PASS/FAIL
                  → spent += usage_by_run_id delta ; build decision object
                  → write iterations/NNN-summary.md ; update loop.json
                  → STOP if: verify PASS (done) | spent≥budget | N≥max-iter |
                             approval-pending | no next_action
       → bounded progress line to chat
  → terminal verdict → /renmark:finish (gated: merge/release approval, REQ-12)
```

## Error handling / stop & safety

- Verify FAIL with a clear `next_action` + budget/iters remaining → continue.
- Verify FAIL with no actionable next step / no fresh evidence → `stalled`, STOP.
- `spent ≥ budget` checked BEFORE each iteration → `budget-hit`, STOP (never
  exceed the approved ceiling; escalation needs a new upfront approval).
- A loop never merges/releases/PRs or makes destructive changes autonomously —
  it reaches `awaiting-approval` and stops (REQ-12); commits to the feature
  branch are allowed (safe/revertable).
- `loop.json` write before each iteration returns → resumable from any crash.
- Loop driver never raises into chat; ledger/verify read failures degrade to a
  STOP with a clear status, not a crash.

## Success criteria

- `/renmark:loop "<goal>"` runs ≥1 iteration, verifies goal-backward, and stops
  at a terminal status; the upfront gate is the ONLY approval prompt during the run.
- Budget enforced: a loop stops at `budget-hit` when ledger spend for its run_id
  reaches the ceiling (token or $-converted); never exceeds it.
- `loop.json` + `iterations/NNN-summary.md` written each iteration; `/renmark:resume`
  recovers iteration index + remaining budget + pending step (zero LLM).
- Context hygiene held: the loop driver reads only verify metadata + ledger +
  bounded summaries (asserted in tests / review).
- Pure-stdlib; `usage_by_run_id` aggregates real ledger spend; `pytest`/`ruff`/
  `mypy`/`lint_all` green; no new dependency.
