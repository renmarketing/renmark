+def iter_rule_blocks(text: str) -> list[tuple[str, str]]:
+    """Extract well-formed ``BEGIN:<name>``…``END:<name>`` rule blocks from ``text``.
+
+    Returns ``[(name, verbatim_block), …]`` in document order, where
+    ``verbatim_block`` runs from the start of the BEGIN marker's line through
+    the end of the END marker's line (trailing newline included if present).
+
+    Reuses ``_BEGIN_RE`` / ``_END_RE`` so the linter and any consumer (e.g.
+    ``init.merge_rule_blocks``) share one marker source of truth. Malformed
+    blocks — duplicate, unbalanced, or out-of-order — are SKIPPED, never
+    returned, so a caller can safely insert only what it gets back. This is
+    intentionally non-strict (unlike ``lint_template_rule_blocks`` which
+    reports those as issues); it's the merge-safe view of the same data.
+    """
+    begins = [(m.start(), m.group(1)) for m in _BEGIN_RE.finditer(text)]
+    ends = [(m.start(), m.group(1)) for m in _END_RE.finditer(text)]
+
+    begin_names = [name for _, name in begins]
+    end_names = [name for _, name in ends]
+
+    blocks: list[tuple[str, str]] = []
+    for b_pos, name in begins:
+        # Skip names that aren't a clean 1:1 balanced pair.
+        if begin_names.count(name) != 1 or end_names.count(name) != 1:
+            continue
+        e_pos = next(pos for pos, n in ends if n == name)
+        if e_pos < b_pos:
+            continue  # out of order — skip
+        # Expand to whole-line boundaries: line start of BEGIN, line end of END.
+        line_start = text.rfind("\n", 0, b_pos) + 1
+        end_marker = next(m for m in _END_RE.finditer(text) if m.group(1) == name)
+        nl = text.find("\n", end_marker.end())
+        line_end = len(text) if nl < 0 else nl + 1
+        blocks.append((name, text[line_start:line_end]))
+    return blocks

   178	def iter_rule_blocks(text: str) -> list[tuple[str, str]]:
   179	    """Extract well-formed ``BEGIN:<name>``…``END:<name>`` rule blocks from ``text``.
   180	
   181	    Returns ``[(name, verbatim_block), …]`` in document order, where
   182	    ``verbatim_block`` runs from the start of the BEGIN marker's line through
   183	    the end of the END marker's line (trailing newline included if present).
   184	
   185	    Reuses ``_BEGIN_RE`` / ``_END_RE`` so the linter and any consumer (e.g.
   186	    ``init.merge_rule_blocks``) share one marker source of truth. Malformed
   187	    blocks — duplicate, unbalanced, or out-of-order — are SKIPPED, never
   188	    returned, so a caller can safely insert only what it gets back. This is
   189	    intentionally non-strict (unlike ``lint_template_rule_blocks`` which
   190	    reports those as issues); it's the merge-safe view of the same data.
   191	    """
   192	    begins = [(m.start(), m.group(1)) for m in _BEGIN_RE.finditer(text)]
   193	    ends = [(m.start(), m.group(1)) for m in _END_RE.finditer(text)]
   194	
   195	    begin_names = [name for _, name in begins]
   196	    end_names = [name for _, name in ends]
   197	
   198	    blocks: list[tuple[str, str]] = []
   199	    for b_pos, name in begins:
   200	        # Skip names that aren't a clean 1:1 balanced pair.
   201	        if begin_names.count(name) != 1 or end_names.count(name) != 1:
   202	            continue
   203	        e_pos = next(pos for pos, n in ends if n == name)
   204	        if e_pos < b_pos:
   205	            continue  # out of order — skip
   206	        # Expand to whole-line boundaries: line start of BEGIN, line end of END.
   207	        line_start = text.rfind("\n", 0, b_pos) + 1
   208	        end_marker = next(m for m in _END_RE.finditer(text) if m.group(1) == name)
   209	        nl = text.find("\n", end_marker.end())
   210	        line_end = len(text) if nl < 0 else nl + 1
   211	        blocks.append((name, text[line_start:line_end]))
   212	    return blocks

<!-- BEGIN:parallelism-rule -->
## Parallelize large plans
When implementing a multi-step plan (4+ tasks, or any task list with independent
leaves), dispatch sub-agents in parallel. **Single-message, multiple `Agent` tool
calls** — that's how they run concurrently. Sequential dispatch is the slow path.

- Independent file scopes → parallel. Two agents touching the same file must be sequential.
- Read-only verification → always parallel alongside code work, never after.
- Long-running probes → background `Bash` with `run_in_background: true`.
- Brief each agent: goal, file scope, what NOT to touch, deliverable. Tell them skip commits.
<!-- END:parallelism-rule -->

<!-- BEGIN:single-branch-rule -->
## Stay on main for small changes
Hotfixes, config edits, and single-file changes land directly on `main`.
Use `/renmark:feature` for new features or significant refactors — it creates
a branch, runs the full pipeline, and offers PR on finish.
<!-- END:single-branch-rule -->

Summary: Critical `0` | Major `4` | Minor `1` | Nit `0`

- [renmark/lint.py](/home/renmark/projects/ai-system/renmark/lint.py:174)  
  Severity: Major  
  `_BEGIN_RE` / `_END_RE` match `BEGIN:name` and `END:name` anywhere in the file, so prose, code fences, or examples can be mistaken for managed markers and cause `merge_rule_blocks()` to skip a missing block or anchor insertion at the wrong place.  
  Fix: make the marker regexes match only full managed marker comments on their own lines (for example `<!-- BEGIN:name -->` / `<!-- END:name -->`) and use that stricter parser everywhere.

- [renmark/init.py](/home/renmark/projects/ai-system/renmark/init.py:1370)  
  Severity: Major  
  The malformed-marker safeguard only treats stray `BEGIN:name` markers as “present”; an orphan `END:name` is treated as absent, so the merge will insert a fresh canonical block and leave the dangling `END` behind, further corrupting the file.  
  Fix: detect unmatched `END:` markers too and fail or skip that file entirely instead of merging into it.

- [renmark/init.py](/home/renmark/projects/ai-system/renmark/init.py:1417)  
  Severity: Major  
  If an earlier block has `BEGIN:name` without a matching `END:name`, `_insert_block()` falls back to the next anchor and can insert later canonical blocks inside the still-open malformed block, violating the non-destructive guarantee.  
  Fix: pre-validate the target for balanced markers and abort merging that file on any malformed block rather than trying to place other blocks around it.

- [renmark/init.py](/home/renmark/projects/ai-system/renmark/init.py:1367)  
  Severity: Major  
  `merge_rule_blocks()` claims to back-fill both `CLAUDE.md` and `AGENTS.md`, but `AGENTS.md.template` has no managed `BEGIN:/END:` blocks, so existing AGENTS files can never receive missing rules and silently drift from CLAUDE.  
  Fix: either add managed markers to `AGENTS.md.template` and merge them, or stop advertising AGENTS back-fill and handle AGENTS sync with a different explicit mechanism.

- [renmark/init.py](/home/renmark/projects/ai-system/renmark/init.py:1456)  
  Severity: Minor  
  `run()` converts any `merge_rule_blocks()` failure into exit code `1`, even though the new contract says malformed/corrupted marker cases should be exit `2`, so callers cannot distinguish bootstrap/template failures from user-fixable document corruption.  
  Fix: raise a dedicated corruption error from the merge path and map that to exit `2`, reserving exit `1` for genuine scaffold/template availability failures.
