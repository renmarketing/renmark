## Findings

### MAJOR — deferrable

**`renmark/cli/commands.py:405-406` — `diff_result.returncode` never checked**

`cmd_review_package` checks `stat_result.returncode != 0` before proceeding (line 393),
but does NOT check `diff_result.returncode` (line 405-406). If `git diff` fails after
`git diff --stat` succeeds (edge: race condition on a packed ref, filesystem issue,
pathological ref disambiguation), `diff_body` is silently empty and a syntactically valid
but content-empty package file is written and its path returned as success (rc=0).

The orchestrator receives a path pointing to a package with an empty `## Diff` section,
with no indication of failure. The reviewer subagent reads it and sees no diffs — a
silent false-success.

Fix: add `if diff_result.returncode != 0: print(f"ERROR: ...", file=sys.stderr); return 2`
after line 406 (before the truncation block). Low-frequency edge case but violates
"explicit uncertainty over silent success" (CLAUDE.md § Artifact existence ≠ correctness).

Tests do not catch this: `test_review_package_bad_ref_returns_error` uses bad refs for
BOTH endpoints, so stat fails first; no test exercises stat-success + diff-failure.

### MINOR — deferrable

**`renmark/config.py` / P11 — `is_proactive()` has no call-site in the Python runtime**

`is_proactive(repo)` is defined and tested (11 tests covering storage/retrieval), but
nothing in the Python runtime calls it to gate auto-routing behavior. The enforcement
model is LLM-instruction-based: `CLAUDE.md.template` and `AGENTS.md.template` mention
`--set-proactive false`. However, running `renmark-execute --set-proactive false` on
a project does NOT update that project's `CLAUDE.md`/`AGENTS.md` — it only writes
`config.json`. An LLM that already loaded CLAUDE.md will not observe the change until
the file is regenerated.

This is either: (a) by design, relying on the user manually running `/renmark:init`
to regenerate `CLAUDE.md` after toggling, or (b) a missing integration step. Either
way, the test suite cannot detect that `--set-proactive false` has no observable
effect on auto-routing behavior — the tests only prove persistence, not enforcement.

No code is wrong; the architecture gap should be documented or closed.

---

**`tests/test_engine_resume_crosscheck.py:188` — integration test assertion is weak on orphaned-task non-execution**

`test_resume_warns_on_orphaned_skip_entry` asserts:
1. "orphaned" or "cross-check" in output (correctly verifies the warning).
2. `"(prev run)" not in out` — claimed to prove the orphaned task was not skipped.

But `(prev run)` is the string printed when a task is SKIPPED as done. If task 1-3
are NOT in the git log and codex is unavailable, they attempt to run and FAIL — they
never print `(prev run)`. The assertion is vacuously true regardless of whether the
cross-check fired: tasks 1-3 were never committed in that git repo, so `(prev run)`
would not appear even if the orphaned-index check was entirely removed.

The test DOES correctly verify the warning fires for index 5. The non-execution claim
is unverified — a broken cross-check that included orphaned indices in safe_to_skip
would still pass this test as long as the warning was emitted.

Fix: assert that task index 1 was NOT logged as `DONE` / skipped, rather than
checking for absence of `(prev run)` (which was never expected here anyway).

**`renmark/cli/commands.py:293-295` — double int-coerce in `cmd_task_brief`**

`task_index` is coerced to `int` both in the caller (`_engine.py:1146`) and inside
`cmd_task_brief` itself (lines 293-295). The internal coerce has a comment explaining

misleading about what the CLI actually passes.
