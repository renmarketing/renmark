## 1. `renmark/hygiene.py:196` — Major

**Lifecycle-referenced artifacts are compared as repo-relative paths during scanning**, so any lifecycle entry stored as an absolute path (for example `artifact_update=("verification", str(artifact_path))` from the verify flow) is treated as unreferenced and can be archived anyway once it becomes stale.

**Fix:** Normalize artifact refs to a single canonical form before comparison, for example by resolving every lifecycle ref under `repo` and comparing resolved absolute paths instead of raw strings.

## 2. `renmark/memory.py:391` — Major

**`dedupe_memory_log()` deduplicates only `##` sections**, but the real append-only logs store entries as `###` blocks in `features.md` and `bugs.md`, or as bullets in `learnings.md`. So duplicate real-world entries are never removed outside the synthetic H2-shaped tests this branch added.

**Fix:** Parse each supported log according to its actual on-disk schema and dedupe at that entry granularity.

## 3. `renmark/memory.py:461` — Major

**`age_out_memory_log()` uses the same `##`-section parser**, which means it either never ages out actual entries (e.g. learnings bullets), or archives an entire top-level section based on one date instead of pruning individual feature/bug entries.

**Fix:** Rework age-out parsing to operate on individual log entries and extract dates from the real entry headers/body format before moving only those entries.

## 4. `renmark/lifecycle.py:358` — Major

**`validate_artifact_refs()` accepts absolute paths and `..`-escaping relative paths as valid lifecycle artifacts**, so `/renmark:resume` can trust files outside the project's `.renmark/` tree and quietly violate the project-boundary invariant.

**Fix:** Reject or at least WARN on any artifact path that does not resolve inside the allowed project subtree before checking existence or metadata.

## 5. `renmark/cli/_engine.py:779` — Minor

**The new escalation-to-ADR hook is effectively dead code** because `_record_escalation()` only logs a decision when `escalated_to` is non-`None`, and no call site in `_engine.py` passes that argument.

**Fix:** Thread the destination executor through the actual escalation paths, or remove the unused parameter until a real caller exists. **Note:** this was explicit in T4's plan spec — the optional kwarg was designed as opt-in to avoid breaking existing call sites. Real callers should be threaded in a follow-up patch as escalation contexts get fleshed out.
