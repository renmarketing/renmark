Summary: Critical 1, Major 5, Minor 1, Nit 0.

- `renmark/scan.py:507` — Critical — The advertised read-only Bash denylist only matches `git` when the mutating verb comes immediately after it, so commands like `git -C repo commit`, `git --git-dir=... commit`, or shell aliases/functions can bypass the hook and mutate the repo from a scheduled scan. Fix: stop relying on a regex over raw shell text and either execute only an explicit allowlist of verifier commands or parse shell words/options before blocking all mutating git subcommands.

- `renmark/cli/commands.py:83` — Major — `cmd_scan()` always returns `0`, even when findings exist or checks failed to run, so a scheduler cannot distinguish a clean scan from a dirty/partial one despite the skill contract saying findings should exit non-zero. Fix: return `1` for findings and a distinct non-zero for partial/failed scans, keeping `0` only for a clean run and `--emit-cron`.

- `renmark/scan.py:443` — Major — If a ledger entry exists but its `backlog_id` points to a missing/corrupt item, the changed-fingerprint branch updates the ledger anyway and skips creating a replacement item, which permanently suppresses that finding on later runs. Fix: treat `read_item(...) is None` as a stale-ledger miss and recreate a fresh backlog item before updating the ledger entry.

- `renmark/scan.py:334` — Major — Report paths are only date-scoped, so multiple scans on the same day overwrite the same artifact and all backlog `evidence_path` links for that day silently retarget to the newest report. Fix: include time or another unique suffix in the report filename and pass the actual written path into `propose_findings()` instead of recomputing it.

- `renmark/scan.py:429` — Major — Proposal dedup is an unlocked load-check-write-save cycle over `proposals.json`, so overlapping scheduled scans can both observe a finding as new and create duplicate backlog items before either ledger write lands. Fix: serialize proposal updates with a file lock or other atomic compare-and-swap around the ledger read/update/write sequence.

- `renmark/scan.py:462` — Major — `propose_findings()` calls `backlog.next_id()`, which writes a placeholder backlog file as a side effect, so if the subsequent `write_item()` fails the scan still mutates backlog state and leaves a ghost item behind. Fix: use an ID allocator with no write side effect, or explicitly roll back the reserved placeholder when the real item write fails.

- `renmark/cli/_engine.py:999` — Minor — `--propose` and `--emit-cron` are parsed as global flags with no validation, so invoking them without `--scan` falls through to unrelated CLI paths instead of failing fast. Fix: make those flags mutually dependent on `--scan` in argparse and reject invalid combinations explicitly.
