## Findings

1. **Reject-without-write is correct.** `append_ledger_event` validates
   (`type` lookup, non-empty `ts`, then `validate_event`) strictly before any
   file I/O; `LedgerValidationError` is raised before `path.open()` is ever
   reached. `test_append_ledger_event_rejects_malformed_work_result` and
   `test_append_ledger_event_rejects_empty_ts` both assert the ledger file
   does not exist afterward. Confirmed correct.

2. **Reader resilience confirmed.** `read_ledger_events` returns `[]` for a
   missing file (checked via `path.exists()`), and per-line `json.loads`
   failures / non-dict lines are `continue`d rather than raised. One corrupt
   line cannot break the rest of the stream. Matches contract's failure
   behavior for reads.

3. **All four wiring call sites are real, not stubs, and best-effort.**
   - `_engine.py`: WorkOrder emitted right before `_execute_task`, WorkResult
     right after, both wrapped in bare `try/except Exception: pass`.
   - `scan.py write_report`: InspectionReport emitted after the real report
     artifact is written, same best-effort wrapping.
   - `pause.py write_pause`: Escalation emitted after the PAUSED file write,
     same best-effort wrapping; this is the single canonical `write_pause`
     writer, so it covers all pause callers per the commit message's claim.
   - `tests/test_ledger_wiring.py` proves each site by exercising the real
     function (monkeypatching only `_execute_task`/`codex_available`, not the
     ledger calls) and reading the ledger back — not a source-text grep.

4. **F2/F5 schema-only fields confirmed not wired.** `grep` for
   `is_repair|repairs_finding_ref|is_replannable|replan_evidence` outside
   `renmark/ledger.py` finds exactly one hit: `pause.py` passes
   `is_replannable=False` as an explicit literal (same as the dataclass
   default) when constructing an `Escalation` — this is not a
   `ReplannableEscalation` construction path, no caller ever passes
   `replan_evidence` or `is_repair=True`/`repairs_finding_ref`. F2/F5 remain
   carried, not re-opened, as the contract requires.

5. **Acceptance evidence captured.** Ran a scratch script (tmpdir, not
   committed) appending one WorkOrder, one WorkResult, one InspectionReport,
   one Escalation, then `read_ledger_events` — reconstructed "what was
   ordered / what came back / what was inspected / what was escalated" from
   the ledger stream alone. Output matched expectations (4 events,
   round-tripped correctly, kind-filtered reads worked).

6. No bugs, gaps, or scope-creep found. `order_id = f"{run_id}-{task.index}"`
   in `_engine.py` is a reasonable synthetic ID given tasks have no
   pre-existing dispatch UUID; not flagged as an issue since nothing in the
   contract requires UUID uniqueness guarantees beyond this run.
