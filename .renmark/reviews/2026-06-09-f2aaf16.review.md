# Codex review — reporting-and-usage-analytics Part 2 (1cf559a..HEAD)

Focus: correctness + quality (default). Engine: codex exec --sandbox read-only.

Summary: Critical 0, Major 6, Minor 2, Nit 0

- `renmark/cli/commands.py:15` — Major — `cmd_usage` still short-circuits on an empty/missing `usage.jsonl`, so it never delegates to `build_usage_view`/`render_usage_md`, which hides paused-run/local-limit state and drops the mandatory disclaimer on no-usage repos. Fix: remove the early return and always render the bounded usage view, letting the renderer show zero usage.

- `plugin/skills/orchestrate/SKILL.md:102` — Major — the Tier-1 preflight checks `view.get("limit_exceeded")`, but `renmark.usage.build_usage_view()` does not return any `limit_exceeded` field, so this pause path cannot work as written. Fix: either add an explicit boolean to `build_usage_view()` or have the skill derive the breach from existing `percent`/`limits` fields.

- `plugin/skills/orchestrate/SKILL.md:190` — Major — the integration prose tells callers to pass `verifier_result=<exit-code summary>` into `analytics.record_task_run()`, but `analytics._agg_tasks()` only counts simple `pass`/`fail` verdict strings, so verification-failure analytics will be silently wrong. Fix: record a normalized verdict token such as `pass` or `fail` in `verifier_result`, and keep any human-readable tail in a separate field if needed.

- `plugin/skills/finish/SKILL.md:94` — Major — this snippet reads `s.verification_result`, but `LifecycleState` has no such attribute, so feature reports and feature-run analytics will always record an empty verification result. Fix: pull verification status from the verification artifact/metadata or from a real lifecycle field instead of the nonexistent attribute.

- `plugin/skills/finish/SKILL.md:127` — Major — `record_feature_run(status=s.stage)` writes lifecycle stages like `verified`, `ready-to-release`, or `released`, but analytics classifies feature success/block state only from `shipped`/`pass`/`fail`-style statuses, so shipped/blocked feature counts will be wrong. Fix: map lifecycle stages to analytics statuses before recording, or widen the analytics classifier to understand lifecycle stage names.

- `plugin/skills/loop/SKILL.md:175` — Major — the prose records `analytics.record_loop_run()` once per iteration, but `analytics._agg_loops()` treats each row as a whole loop run, which will inflate loop totals and distort success rate and average-iterations reporting. Fix: record one `loop_run` only at terminal completion/pause, or introduce a separate per-iteration event type instead of reusing the whole-loop ledger.

- `plugin/skills/loop/SKILL.md:121` — Minor — the `classify_usage_pause()` call omits both `repo=` and `limits=`, so the documented fallback to the next local rolling-window boundary cannot happen and the pause will usually degrade to the generic 60-minute retry unless a provider reset time is present. Fix: pass the current repo and the relevant limits dict into `classify_usage_pause()` when the pause is driven by local-usage state.

- `plugin/skills/finish/SKILL.md:88` — Minor — the canonical snippet uses `subprocess.check_output(...)` without importing `subprocess`, so a literal implementation of the documented flow will fail immediately. Fix: add `import subprocess` to the snippet.

No findings on the `.gitignore` ordering: the `*.jsonl` ignore does not shadow `summary.json` or `limits.json`. I also did not find any new `datetime.now()` usage in the changed surface; the new code paths shown here use `state.now_iso()`.
