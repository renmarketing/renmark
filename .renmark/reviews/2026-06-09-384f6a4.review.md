Summary: Critical 2, Major 7, Minor 1

`renmark/reports.py:60-62`
Severity: Critical
Description: `feature_reports_dir()` joins `slug` directly into the output path, so an absolute slug or one containing `..` escapes `.renmark/reports/features/` and lets report writes target arbitrary files.
Fix suggestion: Reject absolute paths and path separators in `slug`, or normalize to a safe filename/slug before joining.

`renmark/reports.py:250-254`
Severity: Critical
Description: `write_run_report()` trusts both `kind` and `run_id` as path components, so `../` or absolute values can traverse out of `.renmark/reports/` and overwrite unrelated files.
Fix suggestion: Enforce `kind in RUN_REPORT_KINDS`, sanitize `run_id` to a safe basename, and reject any path component that is absolute or contains traversal.

`renmark/usage.py:153-167`
Severity: Major
Description: Per-provider percentages are computed from the same aggregate `rolling_5h`/`weekly` totals for all rows, so mixed Claude/Codex ledgers overstate each provider’s local-limit usage by charging both against the combined total.
Fix suggestion: Filter window totals by `provider` before calling `_provider_percent`, or have `usage_last_5h`/`usage_last_week` accept an optional provider filter.

`renmark/usage.py:208-215`
Severity: Major
Description: `_compute_resume_after()` returns `provider_reset_at` verbatim and returns `""` when `now` is unparseable, so `classify_usage_pause()` can emit a past, naive, or empty `resume_after` for a `usage_limit` pause.
Fix suggestion: Parse and normalize `provider_reset_at`, clamp any past value to a future retry time, and guarantee a non-empty aware ISO timestamp even when `now` is malformed.

`renmark/usage.py:213-215`
Severity: Major
Description: The “local 5h window” fallback is implemented as `now + 5h`, which is not the 5-hour window boundary and can keep a run paused for nearly a full extra window after the limit should clear.
Fix suggestion: Compute the actual local-window resume point from the current rolling-window boundary or earliest in-window expiry, not by blindly adding five hours to `now`.

`renmark/state/pause.py:77-82`
Severity: Major
Description: `read_pause()` raises on corrupt JSON or unexpected keys, and `build_usage_view()` calls it unguarded, so one bad `PAUSED` file breaks the “non-raising” usage view path.
Fix suggestion: Catch `OSError`, `JSONDecodeError`, and `TypeError` in `read_pause()` and return `None` for unreadable/incompatible pause files.

`renmark/analytics.py:288-305`
Severity: Major
Description: `_agg_features()` only treats status `"completed"` as shipped, but the writer/tests use `"PASS"` for successful feature runs, so completed counts and `shipped_names` silently stay wrong for normal success cases.
Fix suggestion: Normalize feature statuses to one canonical vocabulary, or treat `"pass"`/`"completed"` equivalently during aggregation.

`renmark/analytics.py:432-443`
Severity: Major
Description: Summary writes use a fixed sibling temp file (`summary.json.tmp`), so concurrent `aggregate()` calls can race by overwriting or unlinking each other’s temp file and produce lost or mismatched summaries.
Fix suggestion: Use a unique temp filename per write (for example via `tempfile.NamedTemporaryFile(delete=False, dir=path.parent)`) before `os.replace()`.

`renmark/reports.py:203-220`
Severity: Major
Description: Report writes use a fixed sibling temp file per destination, so concurrent writers to the same report can race and replace or delete each other’s temp file before `os.replace()`.
Fix suggestion: Use a unique temp file per write and only `os.replace()` the specific temp file created by that writer.

`renmark/analytics.py:462-495`
Severity: Minor
Description: `aggregate()` claims bounded summaries but returns unbounded maps such as `events`, `tokens.by_provider`, `tokens.by_model`, and `branch_dispositions`, so a ledger with many distinct keys can still balloon the summary payload.
Fix suggestion: Cap or rank these dictionaries before returning them, the same way `by_feature`, `shipped_names`, and `common_failure_reasons` are already bounded.
