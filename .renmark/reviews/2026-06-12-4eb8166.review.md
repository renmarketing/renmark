Summary: Critical 0 | Major 3 | Minor 2 | Nit 1

- `renmark/plan_lint.py:295` — `Major` — `_check_fable_declared` uses `capabilities.top_tier(repo_root)`, so `RENMARK_TOP_TIER=fable` lets an undeclared repo pass a check that the docs describe as requiring a declared `top_tier: fable`, and `tests/test_plan_lint.py:373-431` has no regression for that bypass.
  Fix: gate on the file declaration itself (`read_tiers(...).get("top_tier") == "fable"` or a dedicated helper like `has_declared_top_tier`) and add an env-override test that must still BLOCK.

- `renmark/lifecycle.py:605` — `Major` — `skill_preamble()` emits the literal text `declared top tier: fable` based on the effective tier, so `RENMARK_TOP_TIER=fable` can make an undeclared repo claim a declaration it does not have, contrary to the wording surfaced by `plugin/skills/brainstorm/SKILL.md:31`.
  Fix: either key this hint off the file declaration only, or change the message to “effective top tier: fable” and add a test for env-only override behavior.

- `renmark/cli/_engine.py:419` — `Major` — the dry-run preview only reprices `fable→opus` when `est_cost_usd is None`, so a plan with an explicit fable estimate can display `fable→opus` while still charging the stale fable rate, and `tests/test_engine_budget_and_rollback.py:291-374` misses this path.
  Fix: recompute or override the displayed cost whenever `effective_executor()` downgrades the executor, regardless of whether `est_cost_usd` was prefilled, and add a regression with explicit `est_cost_usd`.

- `renmark/capabilities.py:62` — `Minor` — `read_tiers()` stops only on lines that literally start with `## `, so a hand-edited but still valid Markdown heading with leading spaces (for example `  ## Learned overrides`) will not terminate the Model tiers block and can leak later keys into the parser.
  Fix: detect the next heading with stripped or left-stripped text (`raw_line.lstrip().startswith("## ")`) and add a malformed-block test with indented headings.

- `renmark/plan_lint.py:392` — `Minor` — the new declaration check is bound to `Path.cwd()` rather than the plan file’s repo, so linting a plan from another checkout can consult the wrong `.renmark/memory/routing.md` and misclassify `fable` tasks.
  Fix: derive `repo_root` from the plan path (or plumb it in explicitly) instead of assuming the caller’s CWD.

- `renmark/capabilities.py:78` — `Nit` — top-tier resolution is exact-case only, so `RENMARK_TOP_TIER=FABLE` or `top_tier: Fable` silently falls back to `opus`, and `tests/test_capabilities.py:44-124` does not pin mixed-case inputs.
  Fix: normalize env/file values with `.lower()` before validation and add mixed-case coverage.
