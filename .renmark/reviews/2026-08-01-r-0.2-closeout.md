evidence (unchanged fast-path behavior, unchanged non-fast-path behavior,
full suite green — 1726/31, reproduced fresh in this review, not re-cited).
The remaining 5 criteria are honestly PARTIAL, not PASS, for the same root
cause repeated five times: **WP-5 built every new mechanism correctly and
tested it thoroughly in isolation, but none of scope verification, the
R-008 checklist, the replan gate, or the repair-work-order pattern is
actually wired into a live skill or dispatch call site.** Each work
package's own status notes flag this individually and truthfully ("Governor/
skill wiring explicitly deferred," "wiring the validator into an actual
dispatch call site... intentionally left for a follow-up," "only
`orchestrate/SKILL.md`'s prose currently calls it") — this closeout's
contribution is aggregating those five honest individual admissions into
one clear picture: the contract's "Expected result" (a live Worker blocked
on the normal path, a live Inspector/repair split, a live third-attempt
stop, uniformly) has not actually happened in production yet. It has been
proven correct in principle by direct unit tests of the underlying pure
functions.

This is the same "flag it, don't fake it" posture R-0.1 used for its one
gap (no-nested-dispatch as literally-enforced) — none of these five gaps
were discovered by this review; they were already documented by the work
packages that built them. What differs from R-0.1 is scale: R-0.1 had one
honest gap out of five criteria; R-0.2 has five (of eight) in the same
"correct but dormant" state. The `scope-enforcement-generalization-design.md`
§5 recommendation to default to "Option A: no enforcement, gradual opt-in"
was a deliberate, Owner-legible design choice made before any code was
written — so this is not a surprise regression, but the practical result is
that R-0.2 shipped primitives and tests, not yet the live enforcement
behavior the contract's Scope/User-journey sections describe in the present
tense.

### 1. F1 — Normal-path scope enforcement (`renmark/dispatch.py`)

**Still PARTIAL — improved, but only half-wired, and the unwired half is
the half the criterion actually requires.**

- **Construction half — genuinely wired, real call site.**
  `_maybe_scoped_claude_dispatch()` is called directly inside
  `dispatch_wave()` (`renmark/dispatch.py:179`), and `dispatch_wave` is
  itself called from `renmark/cli/_engine.py:735` inside `execute_plan`'s
  real per-wave loop — confirmed by reading the call chain directly, not
  trusting the note. For a single-task, single-file Claude-executor wave
  passing `classify_fast_path`'s existing eligibility signals, a real
  `WorkerScope`/`AgentDispatch` is constructed and stored in
  `WaveResult.scoped_dispatches`. `tests/test_wp8_scope_wiring.py` proves
  this against a real `dispatch_wave()` call, not a mock.
- **Verification/enforcement half — NOT wired anywhere, not even as
  prose.** `verify_wave_dispatch_scopes()` / `WaveScopeViolation` — the
  functions that would actually detect an out-of-scope diff and let a
  caller block/escalate — have **zero callers outside
  `tests/test_wp8_scope_wiring.py`**. `grep -rn "verify_wave_dispatch_scopes"
  --include=*.py .` and the same for `WaveScopeViolation` across
  `renmark/**` return nothing outside the test file and the module that
  defines them. Unlike F4/F5 below, this isn't even reached by skill
  prose: `grep -rn "verify_wave_dispatch_scopes\|WaveScopeViolation"
  plugin/` returns nothing at all. `renmark/cli/_engine.py`'s
  `_process_wave_results()` (the function that actually consumes
  `wave_result` after `dispatch_wave` returns) reads only
  `wave_result.tasks`; it never touches `wave_result.scoped_dispatches`.
  The only trace of the verification step is a human-readable note string
  appended to the task's `.note` field ("scope declared — verify with
  verify_wave_dispatch_scopes after it returns") — advisory text for
  whichever future agent session reads it, not a call.
- **Why this matters:** the engineering-acceptance criterion requires a
  Worker "cannot perform a file operation outside that scope **without
  being blocked or triggering explicit escalation**." Constructing a scope
  object that nothing ever checks does not block or escalate anything. A
  real Scenario-C reproduction through the normal path today would still
  succeed unblocked in production, identically to WP-7's finding — WP-8a
  wired the bookkeeping half, not the enforcement half.

### 3. F3 — R-008 pre-dispatch gate (`renmark/cli/_engine.py`)
