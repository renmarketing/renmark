- `renmark/program.py:190`
  - `Major` — `read_program()` leaks `UnicodeDecodeError` for invalid UTF-8 bytes because the decode happens before the `json.loads()` wrapper, so an existing corrupt file does not consistently raise `ProgramStateError`.
  - Fix: wrap `read_text()` decode failures (`UnicodeDecodeError`) in `ProgramStateError`, or read bytes and decode inside the same strict error-handling block.

- `renmark/program.py:221`
  - `Major` — `write_program()` uses a fixed sibling temp path (`program.json.tmp`), so concurrent writers can clobber each other’s temp file and `os.replace()` can publish the wrong payload or fail nondeterministically.
  - Fix: use a unique temp file in the target directory (`mkstemp`/`NamedTemporaryFile(delete=False)`), flush+fsync it, then `os.replace()` that unique path.

- `renmark/program.py:404`
  - `Major` — `_parse_program()` only type-checks `current_stage_id` and `stage_completion_sha`, but never validates that they reference real stage ids, so corrupt existing state is silently accepted and later logic falls back or misreports instead of failing loud.
  - Fix: after parsing stages, validate `current_stage_id is None or in stage_ids` and that every `stage_completion_sha` key is in `stage_ids`, raising `ProgramStateError` otherwise.

- `renmark/program_driver.py:178`
  - `Major` — `next_stage()` returns the first runnable stage in list order, which means an earlier `pending`/`needed` stage can preempt a later `in_progress` stage and a later runnable stage can be selected even when an earlier stage is already `partial`/`blocked`.
  - Fix: prioritize the active `in_progress`/`current_stage_id` stage first, and stop selection when an earlier stage is in an attention state instead of skipping past it.

- `renmark/roadmap.py:380`
  - `Major` — `reconcile_setup()` rewrites stage/task statuses but never recomputes `current_stage_id`, so a freshly reconciled setup program can still point at `None` or a completed stage and `position()` will report the wrong current stage.
  - Fix: after reconciliation, set `current_stage_id` to the first non-`done` stage (or `None` if all stages are done) before persisting.
