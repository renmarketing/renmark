## Minor

**tests/test_lifecycle.py (new tests) | Missing edge-case test: full/standard skill following a minimal skill cross-domain detection.**

The new test `test_skill_preamble_minimal_skill_still_records_invocation` verifies that a minimal skill writes `last-skill.json`. However, no test exercises the full chain `[full-tier skill A] → [minimal-tier skill B] → [standard/full-tier skill C]` and asserts that C receives the cross-domain hint for B→C. Confirmed working at runtime (`brainstorm(build) → resume(meta) → audit(audit)` correctly fires cross-domain; `brainstorm(build) → resume(meta) → feature(build)` correctly fires cross-domain meta→build), but the invariant is unguarded by a test. If a future change to the `minimal` branch accidentally skips `record_skill_invocation`, this would be invisible until the scenario appeared in production.

Fix: add one test — `[brainstorm] → [resume] → [feature]` — assert hint contains "cross-domain transition".

## Critical Ordering Verdict (a–d)

All four correctness points confirmed:

**(a) standard/full: budget check reads last-skill BEFORE record overwrites it.**
Confirmed. In `skill_preamble()` (lifecycle.py:640–641), for non-minimal tiers `context_budget_check` runs first, then `record_skill_invocation`. Runtime proof: `debug(build) → audit(audit)` yields the cross-domain hint, which could only happen if budget_check read debug's state before audit was written. The test `test_skill_preamble_standard_skill_surfaces_only_cross_domain_hint` implicitly enforces this ordering — if reversed, the test would fail (hint would be None).

**(b) `record_skill_invocation` runs for EVERY tier including minimal.**
Confirmed. The `minimal` branch at lifecycle.py:635 calls `_state.record_skill_invocation(repo, skill, domain)` unconditionally before returning None. Runtime proof: after `skill_preamble(tmp, "resume")`, `last_skill_invocation(tmp)["skill"] == "resume"`.

**(c) A minimal skill returning None does not break downstream cross-domain detection.**
Confirmed. Chain `debug(debug) → resume(meta, minimal) → brainstorm(build)` — brainstorm correctly receives the meta→build cross-domain hint. The minimal skill's record is load-bearing and works.

**(d) Fable hint correctly gated — standard-tier skills cannot emit it.**
Confirmed. Guard at lifecycle.py:652 is `if tier == "full" and skill in SYNTHESIS_SKILLS`. No standard-tier skills (`audit`, `scan`, `inventory`) are in `SYNTHESIS_SKILLS`, and the `tier == "full"` guard blocks the path structurally even if they were added. Runtime proof: `audit` with fable declared in `routing.md` returns None (no hint at all in the same-domain case), never the fable hint.
