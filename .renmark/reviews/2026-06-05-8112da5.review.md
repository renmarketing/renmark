- `renmark/blueprint.py:119`  
  Severity: Major  
  `detect_ui()` does not parse the documented `stack.md` format (`**Frontend:** ...` from `plugin/skills/_shared/scope-contract.md`), so the canonical frontend field is treated as missing and blueprint will spuriously prompt or skip prototype generation.  
  Fix suggestion: Parse the actual bolded field form (and likely list-prefixed variants) explicitly, or switch to a line-oriented parser that normalizes markdown decoration before matching `Frontend`.

- `renmark/blueprint.py:119-124`  
  Severity: Major  
  The inline regex lets `\s*` consume a newline after `Frontend:`, so an empty frontend field followed by `Backend: ...` is misclassified as `True` instead of empty/unknown.  
  Fix suggestion: Restrict inline parsing to the current line only (for example `[^\n]*` after the colon, or iterate line-by-line) and treat blank values as `None`/`False` without reading into the next field.

- `renmark/blueprint.py:88-93`  
  Severity: Major  
  `splice_generated_block()` blindly inserts `new_content`, so if generated content contains `<!-- RENMARK:GENERATED:<id>:END -->` the file becomes structurally corrupted and later re-splices will replace only up to the injected marker, leaving garbage behind.  
  Fix suggestion: Reject or escape reserved marker strings inside `new_content` before writing, and add a regression test that proves marker injection cannot break future splices.

- `plugin/skills/feature/SKILL.md:96-100`  
  Severity: Major  
  The feature workflow tells the subagent to “reconcile” blueprint artifacts against touched files and wave summaries, which contradicts blueprint’s own “read architecture ONLY from `.renmark/memory/project-map.md`” rule and invites fabricated architecture updates from diff context.  
  Fix suggestion: Change this step to invoke `/renmark:blueprint` as-is and let that skill read only `project-map.md` and `stack.md`, with touched files used only to decide whether re-running is worthwhile.

- `renmark/blueprint.py:126-144`  
  Severity: Minor  
  Section-form parsing treats markdown-decorated “none” values such as `- **none**` as a real UI because `_NONE_RE` only matches the bare token, so common markdown formatting flips `False` to `True`.  
  Fix suggestion: Normalize list markers/emphasis before comparison, or parse the first semantic token/value instead of comparing the raw joined markdown text.

- `tests/test_blueprint.py:167-212`  
  Severity: Minor  
  The new tests never cover the repo’s documented `**Frontend:**` format, the empty-after-colon multiline case, or marker-string injection into generated content, so the main parser/splice failure modes currently ship undetected.  
  Fix suggestion: Add tests for canonical `stack.md` lines from the shared scope contract, blank inline values followed by other fields, markdown-decorated `none`, and injected reserved markers in `new_content`.
